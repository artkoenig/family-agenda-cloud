## Resolution

- **Location:** `createHttpApp` (pages, fonts, htmx) moves from `apps/api` into its own package (e.g. `packages/http`), separate from the composition-root package. `apps/api` stays an entry point (binds the port, shutdown, signals).
- **Contract per Instance:** `createHttpApp(application, options)` keeps its name and options (`trustProxy`, `publicUrl`, `agendaAccess` (required), `version`), is exported publicly, and the options become documented API. The embedder passes `publicUrl` (the Family's hostname) and `trustProxy`; when forwarding in the same process it sets `X-Forwarded-*` itself. The Node bindings stay optional. No router and no host mapping in the library (gateway, Phase 2).
- **Static assets:** fonts and CSS are read with `readFileSync` at import (immutable, shared per process); fine here, but 1.7 (publishing) must bundle these files. Noted in the fog.
- **Agenda access when hosted:** no new ticket. The Agenda ID is `randomUUID()` and no unauthenticated listing exists, so the URL already works as a secret link; the existing `openAgendaAccess` policy stays the default. What is missing is link rotation/revocation (ADR-0005); that is a public-repo feature, not a blocker, and sits in the fog as a note.

## Review against the code (main @ 83a960d)

- ❌ **Open Agenda access over the internet contradicts ADR-0005.** ADR-0005: on a listener reachable from the internet an Agenda opens only through a secret, **revocable** Agenda Link; `openAgendaAccess` is for the local listener (`apps/api/src/main.ts:14`).
