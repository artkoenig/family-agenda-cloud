## Question

What is the exact contract: the public repo ships an embeddable Instance for exactly one family and knows no tenants? Define the term "Instance" for the glossary, what an Instance owns (database, adapters, jobs) and what stays outside. Output: ADR draft and glossary entry.

## Resolution

**ADR draft: "The Instance is embeddable" (public repo) + glossary change.**

- **Glossary, Instance:** "The whole system of one Family: its database, adapters and jobs. An Instance serves exactly one Family; a process can run one or several." Avoid: Server, deployment, tenant (the word "installation" is dropped).
- **Instance owns:** the database connection, the Family data, the application logic over it, and the due-ness of its own jobs. It can be started and disposed in-process (close connections, stop jobs) without ending the process.
- **Instance is given (injected, not owned):** `SecretStore`, `BlobStore`, `Extractor`, `Clock`, `JobQueue`. The embedder supplies them and may share them across Instances (one S3 client, one LLM client with quotas, one KMS client). Per-Family scoping (blob prefix, per-Family key) is built by the embedder; the library never assumes adapters are exclusive per Instance.
- **Outside the Instance:** port/hostname routing, creating/deleting/migrating Instances, scheduling across Instances, config files and process environment, Matrix services (Synapse, bridges).
- **No tenants in public code:** no `instanceId`/`familyId` anywhere in the domain, not even in logs. The embedder passes logger and metrics hooks per Instance, already bound to its own identifier.
- **Naming of the outside:** no public glossary term; the ADR says "embedder". The term belongs to the private repo.

## Review against the code (main @ 83a960d)

- ❌ **"The library never assumes adapters are exclusive per Instance" is false for the `SecretStore`.** `secretSweep.sweep()` removes every entry of `secrets.list()` that its own database does not refer to (`packages/application/src/secret-sweep.ts:39-42`). A shared, unscoped store would delete other Families' secrets when one Instance starts. The port contract must say: `list()` returns only this Instance's secrets; add it as a contract-test case (#14). With the master key injected and `EnvelopeSecretStore` kept (see #8), secrets stay in the Family database and the issue does not arise.
- Note: ADR-0016 describes a blob sweep, but `BlobStore` has no `list()` and no blob sweep exists. Harmless for a shared S3 store, but orphaned blobs stay; ADR or code should be aligned.
