## Question

How does the Recovery Kit work, or what replaces it, when the `SecretStore` is KMS-based and no master key file exists? What does the library need to expose or make optional so a hosted Instance neither generates a useless Kit nor leaks one?

## Input from the code review and #18

Proposed answer: the Recovery Kit stays on hosted Instances.

- `EnvelopeSecretStore` keeps secrets in the Family database wrapped with the master key; hosted, the per-Family master key comes from KMS instead of a file (see #8). The kit is that key, so it works unchanged.
- The kit is needed to restore a Backup: secrets in a Backup are wrapped with the source Instance's key and are re-wrapped with the target's on restore (#18). Without it a hosted Family could not move to self-hosting (#5, no lock-in).
- Open: when a hosted Family must confirm the kit (onboarding, #19) and whether the operator keeps a copy (no, if "only ciphertext" from ADR-0006 should hold).

**Comment by artkoenig, 2026-11-07T13:34:09Z**

## Resolution

- **The Recovery Kit stays when hosted**, same content (the Family's master key) and same page, viewable and downloadable any time while the Family exists. It is the way out of the cloud: a Backup restores elsewhere only with it (#18), part of "no lock-in".
- **When it must be confirmed** (forced step in onboarding self-hosted; when hosted none, offered at Backup download and when closing the Family): **handed to "Decide onboarding flow and embedder-set LLM endpoint" (#19)**, decided there.
- **Operator access, stated openly** in the privacy policy and in the ADR that partly supersedes ADR-0004: the operator holds the operator key and can decrypt Family data, using it only for operation; the key is kept apart from databases and backups. The "only ciphertext" promise (ADR-0004/0006) keeps applying to self-hosted backup targets, not to a hosted Instance.
- **Operator key:** only from a Docker secret or env, never in a database, **not in operator backups**, kept separately (password manager, offline). Losing it makes the wrapped Family keys unusable; only the Families' Recovery Kits remain.
- **After a restore** the target Instance has a new master key (secrets re-wrapped, Agenda links change), so the kit counts as **not confirmed**; the old kit does not fit the Instance any more.
- **No operator function to recover a lost kit:** while the Family exists any Admin can view it; with closing the Family it is gone on purpose (GDPR).
