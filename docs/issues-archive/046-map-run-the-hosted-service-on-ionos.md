## Destination

Every decision for running the hosted service on IONOS is made (IONOS product per building block, topology, cost per Family, infrastructure as code, Operator backups and recovery), so the build issues under [Run the hosted multi-Family service](https://github.com/artkoenig/family-agenda-cloud/issues/24) can be implemented. This map plans only; it builds nothing.

## Notes

- Decisions of [Map: Scaling refactorings for hosted family-agenda (Phase 0 + 1)](https://github.com/artkoenig/family-agenda-cloud/issues/1) and [Map: Public entry point of the hosted service (landing page, registration, billing)](https://github.com/artkoenig/family-agenda-cloud/issues/32) stand: public image as shared `api`/`worker`/`cleanup` workloads, one database per Family plus a control database, S3 blobs, Family keys wrapped by the Operator key behind `KeyWrapper` (now a key file, not OpenBao), one address, Matrix messengers never hosted, Operator-set LLM endpoint, Stripe, sign-in through Google or Authentik.
- Why IONOS: location in Germany and its LLM offer (AI Model Hub).
- Placement rule: all Family content and the LLM run at IONOS in Germany. EU services that see no Family content are allowed where IONOS has no fit. Stripe and Google sign-in are external anyway.
- Sizing: start for about 100 Families, design with room up to about 1000.
- Operation: the maintainer alone, best effort, no on-call. Prefer managed services over self-run ones and the simplest compute that fits.
- Private repo: nothing of this goes into the public repo.
- Language: English in tickets; domain terms untranslated (public `GLOSSARY.md` plus this repo's). Skills: `grilling` + `domain-modeling` for decisions, `research` for research tickets (findings in `docs/research/`).

## Decisions so far

<!-- one line per closed ticket -->
- [Research IONOS compute for the three workloads](https://github.com/artkoenig/family-agenda-cloud/issues/47): no container service between VMs and Kubernetes; Managed Kubernetes (2 nodes, about 100 EUR/month net, free control plane, no OS patching) fits best, Cubes with Docker Compose (about 40 EUR/month) is the cheap self-maintained alternative; its `LoadBalancer` is only a static IP on one node, untested on node loss (see docs/research/ionos-compute.md).
- [Research IONOS managed PostgreSQL and Object Storage](https://github.com/artkoenig/family-agenda-cloud/issues/48): fits on paper; database and role per Family over SQL only, no documented count limit; at most 989 usable connections per cluster, fixed by RAM; restore and point-in-time recovery for the whole cluster only; reachable only on the IONOS private LAN; Object Storage in Frankfurt and Berlin without scoped keys, so one service key and prefixes enforced by the app (see docs/research/ionos-postgres-object-storage.md).
- [Research IONOS AI Model Hub for Extraction](https://github.com/artkoenig/family-agenda-cloud/issues/49): fits on paper; OpenAI-compatible, Berlin only, content neither logged nor trained on, 0.10 to 0.65 EUR per 1M input tokens, 5 requests/s per model, no budget per token; to measure: `json_schema` per model and whether `reasoning_effort: "low"` is accepted; candidates Qwen3.8-27B, gpt-oss-120b, Mistral Small 24B; the terms on use for third parties need IONOS's written word (see docs/research/ionos-ai-model-hub.md).
- [Research IONOS platform services around the workloads](https://github.com/artkoenig/family-agenda-cloud/issues/50): compute, Kubernetes, PostgreSQL clusters, Object Storage, DNS, certificates, logging and monitoring are covered as code (Terraform / OpenTofu); missing are a managed key service (OpenBao self-run, nothing to auto-unseal against) and transactional mail (external EU sender), and the provider cannot manage AI Model Hub, tokens (90 days at most) or databases per Family; about 8 incidents in 6 weeks; certifications do not name DBaaS or the AI Model Hub (see docs/research/ionos-platform-services.md).
- [Research IONOS VPS and a later move to IONOS Cloud](https://github.com/artkoenig/family-agenda-cloud/issues/63): VPS L+ only about 4 EUR/month cheaper than one Cube, but a second contract (IONOS SE, AVV EU/EEA), Germany not confirmed, 99 % per year, no API, and no migration path to DCD beyond a manual restore; cheapest sensible start is one Cube in DCD with Docker Compose (see docs/research/ionos-vps.md).
- [Open the IONOS account and an AI Model Hub token](https://github.com/artkoenig/family-agenda-cloud/issues/51): contract 39683376 (Einzelunternehmer); group `ai-model-hub` but no dedicated user yet, token from the main account at `~/.config/ionos/ai-model-hub.token`, expires 2026-11-13; `/v1/models` answers 200 once trailing whitespace is stripped from the token.
- [Measure Extraction on the AI Model Hub](https://github.com/artkoenig/family-agenda-cloud/issues/53): on synthetic German mail `json_schema` works on every model; only Qwen3.8-27B (no misses, about 3.30 EUR per 1000 messages) and gpt-oss-120b (4 of 58 missed, about 0.40 EUR) accept the adapter's `reasoning_effort: "low"`; Mistral Small rejects it; about 0.12 to 1 EUR per Family and month; real mail not yet measured.
- [Decide compute platform and topology](https://github.com/artkoenig/family-agenda-cloud/issues/54): cheapest setup for now. One Basic Cube M in `de/fra` with Docker Compose (`api`/`worker`/`cleanup` ×1, Caddy, Postgres as a container on the NVMe), about 22.50 EUR/month, best effort. WAL archiving to Object Storage is mandatory before registration opens. Postgres moves to IONOS managed at about 100 paying Families, a second Cube, or a tight Cube. Growth: vertical, then workers on a second Cube, then `api` behind an ALB; Kubernetes is reconsidered only there.
- [Decide where OpenBao and Authentik run](https://github.com/artkoenig/family-agenda-cloud/issues/56): no OpenBao, since on one Cube it protects almost nothing. Instead the Operator key is a versioned root-only key file, mounted only into `api`/`worker`/`cleanup`, never in databases or backups, with offline copies in the password manager and on paper (public adapter: [Wrap Family master keys with a versioned Operator key file](https://github.com/artkoenig/family-agenda/issues/357)). Authentik runs on the same Cube with its own database in the same Postgres, single instance, public on its own subdomain, admin paths blocked, admin through an SSH tunnel; it moves in only after the mail sign-in test passes.
- [Choose and register the domain](https://github.com/artkoenig/family-agenda-cloud/issues/52): `family-agenda.cloud`, registered at IONOS SE 2026-11-13 (expires 2027-11-13), no variants; apex = landing page, `app.` = service, `auth.` = Authentik, mail from `no-reply@`; DNS stays at IONOS SE for now (see the infrastructure decision), certificates by Caddy over HTTP-01.
- [Decide Postgres hosting and cluster capacity](https://github.com/artkoenig/family-agenda-cloud/issues/55): start only; Postgres 17 container on the Cube, 3 GB limit, `max_connections` 300 (at most 60 open Instances per `api`/`worker` through the existing LRU cap), no limit on Family databases, control, Family and Authentik databases in one instance; everything about the managed service deferred to the move.
- [Decide infrastructure as code and the release procedure](https://github.com/artkoenig/family-agenda-cloud/issues/58): simplest start, no rollback. Cube, IP, firewall, buckets set up by hand following a runbook; DNS by hand at IONOS SE; `bootstrap.sh` once; secrets in a root-only `.env` (master copy in the password manager); release = pinned image in `compose.yaml` + `deploy.sh` (rsync, pull, up) from the laptop; errors fixed forward, disasters restored from backup; AI Model Hub token rotated by hand every 80 days.
- [Decide Operator backups and disaster recovery](https://github.com/artkoenig/family-agenda-cloud/issues/59): WAL-G in our own Postgres image, WAL every 5 min plus a daily base backup, encrypted, to a bucket in Berlin, kept 14 days; blobs stay in Frankfurt with versioning (14 days), no copy; config in repo and password manager; loss at most about 5 min, downtime best effort; one restore runbook (Cube, point in time, one Family); bucket loss accepted; restore drill before registration opens.
- [Decide monitoring, alerts and logs](https://github.com/artkoenig/family-agenda-cloud/issues/64): dead man's switch at Healthchecks.io (EU, pings only). `health` every 5 min (HTTPS, containers, disk/RAM, WAL archive, overdue backlog, token expiry), `backup` within 26 h, `cleanup` per run; alerts by email and push, no on-call; growth triggers in a CSV on the Cube; logs via rotated Docker `json-file`, no central logging.
- [Research EU transactional mail senders](https://github.com/artkoenig/family-agenda-cloud/issues/66): every hosted candidate has SMTP for Authentik, an API and a DPA; EU-only without a US parent are Scaleway TEM (FR, about 0.55 EUR at 2.5k and 5 EUR at 20k mails/month, content kept 36 h, default cap 10k) and Lettermint (NL, 10 to 25 EUR, 28 d); Brevo and Mailjet are French with US sub-processors, Mailgun and Postmark have US parents; IONOS Mail sends over SMTP but is a mailbox (50 to 500 mails/h, no API, no webhooks, application use unconfirmed), a self-run MTA puts all deliverability on the Operator (see docs/research/eu-transactional-mail.md).
- [Decide the transactional mail sender](https://github.com/artkoenig/family-agenda-cloud/issues/67): one IONOS Mail Basic 1 mailbox `no-reply@family-agenda.cloud` over `smtp.ionos.de`:465 for both Authentik's codes and `api`'s confirmations, chosen for one contract less and automatic DKIM, not for placement (the AVV promises only EU/EEA); the AGB say nothing about application sending, so it is permitted by omission; failed handovers are counted into the existing `health` alert, DSN bounces are read by hand in the maintainer's mail client (which also satisfies AGB 10.2), no bounce code; successor Scaleway TEM at repeated `450` or more than 300 mails/hour.
- [Decide staging](https://github.com/artkoenig/family-agenda-cloud/issues/65): no second environment; the maintainer's self-hosted Instance on the home server is the test place, production itself is tested in the window before registration opens, and each release is guarded by `smoke.sh` run from `deploy.sh` (loud failure, no rollback); only release tags `X.Y.Z` reach production, and the maintainer's own Family is the canary.
- [Decide how plugin containers and their Egress Proxies run on the Cube](https://github.com/artkoenig/family-agenda-cloud/issues/68): one shared container per hosted Source Type (`ics`, `imap`, `webuntis`, matrix not hosted), each with its own Egress Proxy, generated from a cloud-only `plugins.yml`, no memory limits, about 0.8 GB and 6 containers more (about 7 of 8 GB), vertical move to a Memory Cube M as the trigger; the proxy's allowlist request names its Family through a per-call ticket (Family + Source, HMAC) instead of a cross-Family union, so it is scoped per Source — breaking plugin contract 3.0, handed to [Scope an Egress Proxy's allowlist per Source with a per-call ticket (contract 3.0)](https://github.com/artkoenig/family-agenda/issues/358) and a prerequisite for launch.
- [Decide the LLM model and the interim limit per Family](https://github.com/artkoenig/family-agenda-cloud/issues/57): `Qwen/Qwen3.8-27B` for every Family, chosen for quality (58/58 Items against gpt-oss-120b's 54/58) at about 1.00 EUR per Family and month, no automatic fallback; no per-Family cap at launch (volume is bounded by a Family's own Sources), instead a spend alert above 250 EUR/month over the IONOS Billing API (corrected from 50 EUR in [Decide the cost model per Family](https://github.com/artkoenig/family-agenda-cloud/issues/60)) in the `health` cron; a refusing endpoint stays a temporary error, so the worker backoff ([1.3](https://github.com/artkoenig/family-agenda-cloud/issues/11)) and the overdue-backlog alert are launch conditions; model id in `.env`, switched by hand after a harness run; real mail still to be measured.
- [Decide the cost model per Family](https://github.com/artkoenig/family-agenda-cloud/issues/60): about **1.25 EUR per Family and month**, flat across scale — ~1.00 EUR of inference plus ~0.20 of infrastructure; fixed cost is ~26 EUR/month at 100 Families (Cube M, IPv4, mailbox, domain, Object Storage; Postgres still a container) and ~178 at 1000 (Memory Cube M plus managed PostgreSQL at 142), so the LLM is 79 to 85 % of the bill and the only line that scales. Acceptable to go on: yes. Load-bearing assumption, written into the growth CSV and checked against the first month of real usage: 300 messages per Family and month. The price must cover about 3× that volume; at the 4.99 EUR gross the Operator has in mind it covers 3.6×, fixed cost is met at ~10 paying Families, and a Family turns cost-negative above ~1100 messages a month. The tail stays uncapped at launch, successor trigger: one Family above 10 EUR of inference in a month.
- [Decide launch readiness](https://github.com/artkoenig/family-agenda-cloud/issues/71): launch is three stages, not one event — **(a) own Family** (plugin contract 3.0 for `ics`/`imap`/`webuntis`, worker backoff, build issues released and deployed, certificates and DNS, WAL archiving running), **(b) about 5 invited Families by hand** (Authentik mail sign-in under 60 s at three providers, full timed restore drill plus a single-Family restore, Extraction on at least 50 real anonymised messages with no missed Item in a multi-Item message and at least 95 % of dates and times right, AI spend alert live), **(c) registration opens** (capacity check of 120 databases and 60 open Instances instead of a throughput load test, 7-day clean WAL soak, processing agreements with [#62](https://github.com/artkoenig/family-agenda-cloud/issues/62) blocking only this stage, entry point from [#32](https://github.com/artkoenig/family-agenda-cloud/issues/32)); every gate's threshold, measured value and proof live in `docs/launch-checklist.md`, and a gate without a measured value is a failed gate.

## Not yet specified

- Mail that carries Family content (digests, reminders with Task titles): neither IONOS Mail nor an EU sender is covered for it by the placement rule, since no IONOS page names a data centre for Mail Basic. Hangs on [Map: Public entry point of the hosted service (landing page, registration, billing)](https://github.com/artkoenig/family-agenda-cloud/issues/32) deciding whether such mail exists at all.
- Move to IONOS managed PostgreSQL: cluster size and HA, when a second cluster is added and how the register points to it, where the control database lives, pooler, move procedure and downtime (deferred from [Decide Postgres hosting and cluster capacity](https://github.com/artkoenig/family-agenda-cloud/issues/55)). Before it, run the deferred [Try a Family database lifecycle on IONOS managed PostgreSQL](https://github.com/artkoenig/family-agenda-cloud/issues/61) (needs a DCD token; checks SQL role/database rights, pooler, storage classes, retention, single-Family restore).
- Infrastructure expansion, when needed: OpenTofu, Cloud DNS with delegation and DNSSEC, SOPS for secrets, deploying from CI, a restore point before each release, a dedicated IONOS user for the token (deferred from [Decide infrastructure as code and the release procedure](https://github.com/artkoenig/family-agenda-cloud/issues/58)).
- Observability expansion, when needed: IONOS Logging/Monitoring (managed Grafana), dashboards, `api` p95, metrics per Family (deferred from [Decide monitoring, alerts and logs](https://github.com/artkoenig/family-agenda-cloud/issues/64)).
- A throwaway Cube for one risky change, at a notable number of Families: which changes earn it (move to managed PostgreSQL, Authentik or Postgres major upgrade, ingress or certificate change, backup/restore path, first destructive migration) and what it shares with production (nothing writable; never the backup bucket) (deferred from [Decide staging](https://github.com/artkoenig/family-agenda-cloud/issues/65)).

- Setting the price: stays in the entry-point map; this map only supplies cost per Family.
