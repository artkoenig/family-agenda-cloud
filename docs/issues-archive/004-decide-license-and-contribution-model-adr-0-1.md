## Resolution

**Decision (ADR draft for public repo, status: proposed, pending legal review; rewrites ADR-0008 directly since it is still "proposed"):**

- External contributions are welcome but secondary; they must not block the SaaS model.
- SaaS code stays proprietary (publishing it under AGPL, option C, is ruled out).
- Contribution model: **license-grant CLA** (option B: contributors keep copyright and grant a broad, irrevocable right incl. relicensing; no assignment, option G rejected) **plus DCO sign-off**.
- Timing: until the legal review is done, no external code PRs are merged (there are no external contributors today). Afterwards, activate a CLA bot in CI and document it in `CONTRIBUTING.md`.
- ADR-0008's clause "a separate networked program may stay proprietary" is rewritten to match the real architecture (the private repo uses the public packages as a library in the same process).
- Own code: as sole copyright holder, existing code can be used under other terms in parallel.

Follow-up: legal review as a Task ticket (derivative-work line under German/EU law, scope of "Corresponding Source" for a hosted stack, CLA wording for Germany, DCO as license basis, narrowness of any §7 exception). It only gates the ADR's acceptance, not the refactoring plan.

**Comment by artkoenig, 2026-11-07T10:09:24Z**

## Revised decision (maintainer, 2026-11-07)

Replaces the CLA part of the resolution above. Basis: a review of the open points without a lawyer (not legal advice).

- **License stays AGPLv3** for the Instance. Reason: OSI-approved and trusted by self-hosters; keeps competitors from developing the code closed; the maintainer, as the copyright holder, is not bound by the AGPL for their own code, so the proprietary hosted offering stays possible.
- **No CLA. Instead "open source, not open contribution":** external code PRs are not merged. Issues, bug reports, ideas and discussion are welcome; changes are implemented by the maintainer, written anew, never copied from a contribution (German law protects even small code with low originality, § 69a (3) UrhG).
  - Why not a CLA: an exclusive grant to one party for proprietary use is not covered by the "Linux clause" (§ 32 (3) sentence 3 UrhG, which only covers a free simple right *for everyone*), so claims for fair/further remuneration (§§ 32, 32a UrhG) could remain and cannot be waived by contract. No case law on CLAs was found: unclear, not forbidden. Plus bot setup and deterrence.
  - A DCO grants no rights for relicensing; it only attests origin. Not needed while no external code is merged.
  - A CLA can still be introduced later if contributions become important.
- **Plugin SDK (`packages/source-sdk`) under Apache-2.0.** Third-party Source plugins run in the same process (ADR-0010); with an AGPL SDK it would be unclear whether each plugin must be AGPL. A permissive SDK ends that. Nothing changes for the private repo, which uses the AGPL core the maintainer owns.
- Bot commits (Renovate, github-actions) are automated version bumps without protectable originality.
- **ADR-0008** is rewritten accordingly (AGPLv3, no external code contributions, SDK Apache-2.0); `CONTRIBUTING.md` states the policy.
- **Legal review ticket:** no longer needed for the CLA; see the comment there.
