## Resolution

- **Public library API:** whatever the `exports` entry of `composition`, `http`, `application`, `adapters`, `domain`, `contracts` and `source-sdk` reaches. `apps/*` and `tools/*` are never API; internals not exported there are not API.
- **API snapshot:** the existing `sdk-api` / `check-sdk` mechanism in `tools/release` is extended to every library package: a committed `api.txt` per package, and CI fails when the API changes without a matching SemVer bump (removal → major, addition → minor). No new tool (no api-extractor).
- **Import rules (depcruise):** workspace packages import each other only through their `exports` entry (no deep `packages/x/src/...` imports), so the snapshot covers everything in use. `http` imports only `application` and `contracts`, never `adapters` or `composition`.
- **Process state (ESLint):** library packages must not use `process.env`, `process.cwd()` or the process time zone (`Intl.DateTimeFormat().resolvedOptions().timeZone`). Exceptions configured explicitly: `source-matrix` (#9) and the file with `selfHostedAdapters`. Time zone therefore becomes required config (matches the #8 review); `selfHostedAdapters` reads `TZ` from the entry points' config.
- **Module-level state (ESLint):** `no-restricted-syntax` against top-level `let` in library packages and plugins; the plugin hook is the one exception, marked with a justifying comment. Immutable constants and caches (e.g. asset buffers from #10) stay allowed; the isolation test (#9) remains the real safety net.
- **Where it runs:** all in `pnpm check`: isolation test in the regular API suite (`crap`), lint rules in `lint`, import rules in `depcruise`, the API snapshot check next to `check-sdk`. Every violation is an error; no separate CI job.
- **Public rationale:** stable library API for embedding and plugins; several Instances per process, e.g. for tests and preview Instances (`pnpm preview`). No reference to hosting.

**Handed to "Decide publishing the packages (1.7)":** one shared version for all library packages vs one per package, and how package versions relate to the image release version.
