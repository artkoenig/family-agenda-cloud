## Question

How do OCR models (tessdata, ADR-0012) work when containers are stateless and shared by many Families?

## Facts (main)

- Each boot runs `mkdir` on the tessdata directory and links the bundled models (`composition-root.ts`, `ocrModels.linkBundled()`).
- Admins can download further models from `tessdata_fast` into the `tessdata` volume; the Family's OCR languages are stored in the Family database.
- A download by one Family's Admin would land in a directory shared by every Family on that container, and other containers would not have it.

## Options to grill

- All offered languages baked into the image; no downloads when hosted (the language list is fixed by the operator).
- Models in shared object storage (S3), fetched on demand and cached per container.
- What the Admin area shows when hosted (choose languages only, no download).
- CPU cost of OCR in shared containers (limits per Family, queue).

## Resolution (maintainer, 2026-11-07)

**The Operator decides which OCR languages exist, the same for every Family on the Instance; the Family picks its OCR languages from those.** Self-hosted, the self-hoster is the Operator. No download and no deletion of models in the app any more; the OCR containers need no shared state.

**Two knobs, both the Operator's:**
- **Build argument `OCR_LANGUAGES`** in the public Dockerfile, default `deu eng` (plus `osd`). Models are fetched at build time from `tessdata_fast` at the pinned commit and checked against the shipped SHA-256 list. The public CI publishes the default image; the cloud builds **the same Dockerfile at the same release tag** with its own list (no own Dockerfile, no derived image). New containers are ready at once, nothing loads at start — this is how the hosted Instance scales.
- **Start parameter** (e.g. `OCR_EXTRA_LANGUAGES=fra,tur`): additional languages a container downloads at start — the self-hoster's way without an own build.
  - Same source, pinned commit and checksums; a file that does not match is discarded.
  - Target is the model directory; when a volume is mounted there (self-hosted today), files persist and a present file with a valid checksum is not downloaded again.
  - A failed download does not stop the start: the language counts as not available, and it is logged.
  - Optional Operator-set download base URL (mirror); the checksum list always applies.
  - Files placed there by hand still count (offline path); models downloaded by today's Instances keep working.

**Available OCR languages** = models in the image + models in the model directory.

**Admin area:** choose OCR languages from the available ones; no download button; note "further languages are provided by the Operator" (self-hosted: link to the docs of the start parameter). A chosen language that is not available is marked so; scanned attachments are then not read and their Message says why (no silent fallback, as today).

**CPU:** at most N Tesseract processes per worker container at once (Operator setting, default: number of CPUs); an Operator-set page limit per attachment, pages beyond it are not read and the Message says so. Fairness between Families comes from the due-index leases. Per-Family quotas belong to the private repo.

**ADR-0012 is revised** (it is `proposed`): models at build time from `tessdata_fast`, pinned commit and checksums; language list as build argument; start parameter and hand-placed files for self-hosters; in-app download and deletion removed. "All languages in the image" stays a rejected option with its reason (several hundred MB on every Instance, Raspberry Pi).
