## Resolution

- **API:** one unit `worker.dueWork` with `run(): Promise<DueWorkReport>` and `nextDueAt(): Promise<Date | null>`. `run()` does polling, then extraction, then retention if due (retention: `lastPurgeAt + 1 h`, kept in memory; a fresh Instance counts as never purged, so it is due at once). `nextDueAt()` is the minimum over polling (`lastRunAt + interval`), extraction (pending messages and an LLM endpoint: now) and retention. The single calls `pollDue`, `extractPending`, `purge` stay exported for tests and special cases.
- **Semantics:** `Date` when something is due (a past date means now); `null` means nothing is scheduled.
- **Sleeping:** `main.ts` sleeps until `min(nextDueAt, now + maxSleep)` with `maxSleep` = 15 s (was 5 s). The worker gets no signal about new work from the api process, hence the cap. No wake hook in the library; in hosted operation the gateway/scheduler wakes a Family on request (Phase 2).
- **Clock:** a `lastRunAt` in the future counts as due (in `isDue` and `nextDueAt` alike); forward jumps are caught by the cap. Test with the `Clock`.
- **Outside `run()`:** services reconciliation (`worker.services.reconcile()`, every 5 s in `main.ts`, switchable per Instance via 1.2) and the secret sweep (`worker.secretSweep.sweep()`, once at start) are lifecycle/cleanup, not due work.
- **Overlap and report:** `run()` guards itself; a second call while one runs returns the running promise. One `DueWorkReport` merges the poll and extraction reports; logging stays with the caller, with an exported helper `logDueWorkReport(report, log)`. No time or count budget per `run()`; fairness between Families is the Phase 2 scheduler's job.

## Review against the code (main @ 83a960d)

- ❌ **`nextDueAt()` loops hot when the endpoint fails.** Extraction counts as due while messages wait and an endpoint is set. When the endpoint is unreachable or refuses the key, messages stay pending (`packages/application/src/extraction.ts:160-178`), so `nextDueAt()` returns "now" forever: self-hosted the worker calls the LLM endpoint without pause (today the 5 s tick throttles it); hosted, every Family with a broken endpoint is always due. Needs a backoff, e.g. `lastExtractionFailureAt + backoff`.
- Note: today a future `lastRunAt` counts as **not** due (`packages/application/src/polling.ts:148`); the decision changes that behaviour deliberately; worth a test.
- New: "an LLM endpoint is set" means the lookup port from #19 (stored or embedder-set), not the `llm_endpoint` row.
