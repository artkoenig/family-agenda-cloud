## Question

What does an Agenda link look like so that it identifies the Family (which database to open) and the Agenda, cannot be guessed, and works for the Agenda page, its ICS feed and photos? Same format self-hosted and hosted?

## Settled (maintainer, 2026-11-07, see "Decide multi-family Instances in the public image")

- One address for all Families; Agendas are told apart by the **path**.
- Links never expire, have no version or rotation; deleting the Agenda revokes them (amends ADR-0005).

## Options to grill

- `/a/<Family id>/<random secret>`: 128-bit secret stored hashed in the Family database; short (QR codes); Family id in clear so the server knows which database to open.
- Signed token (key per Family): no lookup needed to reject forgeries, but long and needs key handling.
- Self-hosted without a Family id in the path, or the same format everywhere?
- Migration of existing UUID links (`/agendas/:id`), and of ICS subscriptions already made with them.
- Leakage: logs, browser history, `Referer` (e.g. `Referrer-Policy: no-referrer` on Agenda pages).

**Comment by artkoenig, 2026-11-07T13:28:40Z**

## Resolution

- **Format:** `/a/<Family id>/<Agenda id>.<secret>`, the same self-hosted and hosted (one code path). The Family id is random, generated once and stored in the Family database (also self-hosted).
- **Secret = HMAC(Family master key, Agenda id)**, truncated to 128 bits, base64url. Computed on demand, **nothing is stored**: no hash, no `SecretStore` entry, no new column. Opening: read the Agenda id, recompute, compare in constant time; Agenda must still exist. The Admin area recomputes the link (and QR code) whenever needed. A database dump reveals no link, since computing it needs the master key, which is never in Postgres.
- **Revocation:** deleting the Agenda. No expiry, no version, no rotation (amends ADR-0005). The links of an Instance change only when its master key changes (restore into another Instance, #18), where the address changes anyway.
- **Under the link:** everything that hangs off `/agendas/<uuid>` today: page, `/days`, `/activity`, `/tasks/...`, `/feed.ics`, `/manifest.webmanifest`; **new:** `/photos/<member>`, only for Family Members this Agenda shows. `/family-members/<id>/photo` remains for signed-in Admins only (settles the review finding on unauthenticated photos).
- **Old UUID links** stop working, no redirect (it would reveal the secret to anyone knowing the UUID). Acceptable at 0.1.x; release notes tell Families to re-copy links, re-add ICS subscriptions and reinstall home-screen apps.
- **Leakage:** Agenda responses send `Referrer-Policy: no-referrer` (external links already use `rel="noreferrer"`); the secret segment is masked wherever paths are logged; docs note it for operators' own reverse proxies.
