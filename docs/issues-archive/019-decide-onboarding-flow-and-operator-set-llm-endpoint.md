## Question

What does the onboarding that replaces `/setup` look like, and how is the LLM endpoint either configured by the Family (self-hosted) or set by the embedder without the Family seeing it (hosted)? Public-repo feature.

## Settled by the maintainer

- There is an onboarding, from which a Family can also start by restoring a Backup (see the Backup ticket).
- **Self-hosted:** the LLM can be configured in the onboarding, and changed later in the Admin area.
- **Hosted:** the LLM is set by the embedder; the Family does not see it and cannot change it.
- Restoring needs a signed-in Admin; also during onboarding.

## Facts from the code (main @ 83a960d)

- `/setup` creates the first Admin and is open until one exists (`apps/api/src/http/app.tsx:240-274`).
- `extractPending()` returns early when no `llm_endpoint` row exists (`packages/application/src/extraction.ts:166-167`), and `ExtractionRequest` always carries `endpoint` (`ports.ts:740`). An injected `Extractor` alone (decision in #7) therefore never runs on a hosted Instance.

## Proposal to grill

**Flow (self-hosted):** language → first Admin (password or Identity Provider) → signed in → choose "Start new" or "Restore from Backup" → Recovery Kit (new only) → LLM endpoint (skippable, only if not set by the embedder; a reminder stays in the Admin area).

**Flow (hosted):** landing page registers and the embedder creates the Admin (#7) → Admin signs in → same onboarding, without the LLM step.

**LLM port:** a "which endpoint applies" lookup replaces direct reads of the `llm_endpoint` row in extraction, `nextDueAt()` and the Admin area.
- Self-hosted default: the stored row, editable.
- Embedder-set (`Adapters`, e.g. `llm: { managed: endpoint }`): no row, the onboarding step and the Admin page are absent (routes 404), a restored Backup's endpoint and its secret are discarded.
- Also useful for self-hosters who fix the LLM centrally.

## Open

- Does onboarding replace `/setup` fully, or is `/setup` its first step?
- Is "Start new" vs "Restore" one onboarding step, or is restore only reachable from the Backup area after onboarding?
- What does the Family see about the LLM when hosted (nothing, or "provided by the operator")?

## Resolution (maintainer, 2026-11-07)

**Term:** "embedder" is gone (the cloud runs the public image). The one who runs an Instance, self-hoster or cloud provider, is the **Operator** (German UI: "Betreiber"). Operator settings are configuration of the image the Family cannot see or change. Ticket renamed accordingly.

**Onboarding is its own UI in front of the Admin view.** Own layout, no Admin navigation; the Admin view opens only once onboarding is finished, and until then every Admin URL leads back to onboarding. Replaces `/setup` and today's Recovery-Kit gate (`app.tsx:516`). Progress is stored in the Family database (which steps are done); closing the browser resumes at the next open step after signing in. The first step (create the first Admin) is reachable unauthenticated while no Admin exists, self-hosted only; hosted, provisioning creates the Admin.

**Steps, self-hosted:**
1. Language + first Admin (password, or Identity Provider if configured) → signed in.
2. "Start new" or "Restore from Backup".
3. New: Family time zone → save and confirm Recovery Kit → LLM endpoint (skippable) → done.
4. Restore: upload Backup + Recovery Kit → restore → session ends, sign in again → LLM endpoint if none is set → done.

**Steps, hosted:** sign in via Identity Provider → language + time zone → new or restore → done (no forced kit step, no LLM step). Restoring later from the Backup area uses the same code.

**Recovery Kit confirmation:** an Operator setting "force kit confirmation", default on (self-hosted: the Instance is its own single point of failure); off when hosted, where the kit is offered at Backup download and when closing the Family, and viewable any time. **After a restore the kit counts as confirmed** (the Admin just entered it); this replaces "unconfirmed after restore" from the Recovery Kit decision (#17).

**Family time zone:** stored per Family, set in onboarding (prefilled from the browser), changeable in the Admin area; replaces the process time zone, self-hosted too. Existing Instances get today's process time zone on migration.

**LLM endpoint behind a port** (e.g. `LlmEndpointSource`): extraction, `nextDueAt()` and the Admin area read only through it, never the `llm_endpoint` row directly.
- Default: the stored row, set and changed by the Family (onboarding step, Admin page; checked with `health` on save).
- Operator-set: base URL, model and key from the image configuration (key from a file or the vault, never plain in an env variable); no row; onboarding step and Admin page absent (404). Self-hosters may fix it the same way.
- Hosted, the Family sees a read-only line with an Operator-written description (e.g. "Text recognition: IONOS AI Model Hub, data centre Germany"), no URL or model key, for GDPR transparency.

**Skippable LLM step (self-hosted):** without an endpoint, Messages wait unprocessed; a notice stays in the Admin area until one is set.

**Glossary (public repo, at hand-off):** add **Operator** (who runs an Instance and sets its configuration; _Avoid_: embedder, host, provider) and **Onboarding** (the guided start of a Family before the Admin area, ending with a new or restored Family).
