## Resolution

- **Signature:** `bootApplication(config, adapters)` and `bootWorker(config, adapters)` with a required, complete `Adapters` object; the boot functions never build defaults themselves. `selfHostedAdapters(config)` returns today's defaults; `main.ts` wires both.
- **JobQueue:** injected as an adapter (pg-boss stays the default in `selfHostedAdapters`); the port is left unchanged until it has real consumers.
- **Newly injectable:** password hasher, OIDC identity-provider client, tessdata catalog, plugin sources. The master key becomes an optional value/provider in `Adapters` (self-hosting reads it from the file); without it the Recovery Kit is unavailable. Existing overrides (clock, secretStore, blobStore, extractor, textExtractor, connectDatabase) are folded into `Adapters`.
- **Config split:** `readConfig()` stays in the entry points. `ApplicationConfig` holds behavior settings only (no file paths, no `databaseUrl`); everything with I/O lives in `Adapters`.
- **Placement:** the composition root moves into its own package (e.g. `packages/composition`); `apps/api` and `apps/worker` become thin entry points.
- **Public API:** the package's exports are the library API (boot functions, `Adapters`, `selfHostedAdapters`, port types). Later guardrails (1.9) and publishing (1.7) hang off this boundary.
- **Open (fog):** Recovery Kit in hosted operation with a KMS-based `SecretStore`.

## Review against the code (main @ 83a960d)

- ❌ **Master key should be required, not optional.** `EnvelopeSecretStore` keeps secrets in the Family database, wrapped with the master key. A hosted Instance needs no separate KMS `SecretStore`: inject the per-Family master key (from KMS) instead of reading the file. Then the Recovery Kit stays and is the way back to self-hosting and the key for restoring Backups (#18). Proposal: `Adapters.masterKey` as a required value/provider; the file is the self-hosted provider.
- ⚠️ **pg-boss is started but unused.** `bootWorker` starts `PgBossJobQueue` (`apps/api/src/composition-root.ts:377`), and `send`/`work` are called nowhere. Each start creates a pg-boss schema, its own pool and maintenance timers in every Family database. Proposal: remove pg-boss and the `JobQueue` port instead of injecting it.
- ⚠️ **Time zone** defaults to the process's (`composition-root.ts:166`); it must be required per Instance when hosted.
- ⚠️ **tessdata:** each boot runs `mkdir` and `linkBundled()`; an Admin's OCR model download lands in the shared directory and affects every Family. Belongs to making tessdata injectable.
- ⚠️ **Cost per open:** `SourceRegistry.discover` (directory reads), `sourceTypes.start()`, `catalogues.start()` run on every boot; measure for the LRU pool.
- New: `Adapters` gets the LLM setting from #19 (stored vs embedder-set).
